# Contributing to the Enterprise Cybersecurity Learning Repository

Thank you for your interest in contributing to this open-source cybersecurity learning resource! 

Our goal is to maintain the highest standard of technical accuracy, practical real-world relevance, and beginner-to-professional pedagogical clarity across Identity & Access Management (IAM), Security Operations Center (SOC), and DevSecOps.

---

## 📋 Contribution Guidelines

1. **Format**: All documentation must be authored in valid GitHub Flavored Markdown (`.md`). Do not submit PDFs, DOCX, or proprietary binary formats.
2. **Pedagogical Structure**:
   - Provide clear definitions and intuitive real-world analogies where helpful.
   - Detail the step-by-step technical mechanics.
   - Include practical enterprise examples and scenarios.
   - Highlight common misconceptions and industry best practices.
3. **Operational Processes**:
   - Any workflow added to `05_Workflows_and_Processes/` must follow the **Enterprise 8-Point Operational Framework** (Trigger, RACI, Tools, Procedure, Decisions, Escalation, Outcome, Evidence) and include a Mermaid diagram.
4. **Code Quality**:
   - Code snippets (KQL, SPL, Bash, Python, PowerShell, HCL/Terraform, YAML) must be syntactically valid and production-hardened.
5. **No Broken Links**:
   - Ensure all relative links between documents resolve cleanly.

---

## 🛠️ Pull Request Process

1. Fork the repository.
2. Create a feature branch (`git checkout -b feature/new-soc-lab`).
3. Commit your changes with clear, descriptive commit messages.
4. Verify that relative links between Markdown files are valid.
5. Push your branch and open a Pull Request using the standard template.
